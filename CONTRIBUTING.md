# Como contribuir

Sugestões são bem-vindas. A direção do produto pertence a Luiz Criasom. Priorize criar, editar, marcar e reorganizar tarefas com facilidade, mantendo repertório, relógio, metrônomo e persistência.

1. Combine uma tarefa pequena e seu critério de aceite antes de começar.
2. Trabalhe numa branch ou fork separado, com dados fictícios.
3. Abra uma proposta de alteração explicando o problema, o resultado, os arquivos afetados, os testes e as limitações. Inclua imagens sem dados pessoais se a interface mudou.
4. Outra pessoa deve revisar. Alterações de conta, permissões, banco, dependências e automação precisam de revisão técnica específica. Luiz avalia mudanças na experiência.
5. Somente os mantenedores autorizados integram. Integração de código não autoriza publicação, DNS, envio de e-mails ou ativação de cobrança.

Comece concedendo leitura aos colaboradores e escrita apenas aos mantenedores. Forks privados dependem da política do repositório; patches são alternativa. Verifique as proteções realmente disponíveis no plano GitHub utilizado. Um arquivo CODEOWNERS sozinho não força revisão, e não há essa configuração ativada neste pacote.

Rode `npm test` e `npm run check:package`. Teste também os fluxos afetados no navegador. Informe claramente quando algo não foi verificado. Não inclua `.local`, capturas de alunos reais, credenciais, materiais comerciais ou instruções que peçam acesso aos sistemas privados do proprietário.

Decisões de licença, atribuição e condições de contribuição precisam ser combinadas com Luiz. Este pacote não declara uma licença de código aberto nem transfere direitos sobre materiais de cursos.
